## 一、六问正式裁决

### 1. 撤回“终端窗干净”，是否损害其他声明可信度？

**裁决：撤回正确；提高审计可信度，但触发同类声明复查。**

第 262 帧同时是终端窗起始帧，也是发生禁止支撑接触的帧。只要第 262 帧计入正式窗口，窗口就不是全净。此次把具体手部件、桌面 geom 和帧号落到报告字段，是正确的证据修复。<Cite ref="turn164143view0"/>

这次错误不意味着其他数字都不可信，但它提示三个需要特别核查的类别：

- **时间窗类**：起始帧、结束帧、窗口边界是否采用一致的包含规则。
- **聚合类**：`endface_contact_frames` 是盒面存在任意接触的帧数，还是指定 `ff_tip` 接触的帧数？不能未经分解就认为右 148 帧、左 93 帧全是当前唯一有效指垫持续承力。
- **状态类**：命令态 PASS 是否被不恰当地转述成执行态 PASS，尤其是 mass scan 三档全部 `gate1 PASS` 的列。

这次尤其应当审核自动生成的标题、徽章与汇总文本，因为错误很可能发生在“底层数据正确、上层结论越界”的位置。

### 2. 单点接触还能称为抓握吗？

**裁决：不能作为已完成抓握的证据；正式命名应为“双侧端面单点触压”。**

右侧 2.696N、左侧 1.664N 证明当前报告口径下存在接触作用，但不足以证明有稳定的双手夹持能力。

两个手在盒子相对两端各形成一个接触点，理论上可以构成对向夹持的基础；然而稳定夹持还取决于接触法线是否相向、两侧受力是否平衡、力矩是否平衡以及接触处摩擦。

更关键的是，你们的质量实验已经显示当前接触模式很脆弱。

在未证明静态力平衡和扰动鲁棒性之前，我不允许把它称为稳定抓握。

正式状态建议定为：

| 指标 | 状态 |
|---|---|
| `gate1_legacy_command` | 双侧 PASS |
| `executed_endface_contact` | 双侧有接触 |
| `eligible_contact_pads` | 右 1 / 左 1 |
| `stable_grasp` | NOT VERIFIED |
| `object_lift` | FAIL |

因此，v7 的 gate1 PASS 不需要撤回，但它的宣传口径必须限定在命令态几何。

### 3. 0.4kg 是否必须改成 0.15kg？

**裁决：不需要。保留 0.4kg 作为明确标注的参考配置，同时保留三档敏感性实验。**

把默认质量改成 0.15kg 并不能让模型更真实，因为没有实测依据证明原盒就是 150g。

以较轻质量作为默认值来显示严苛，同样是一种任意建模选择。

真正的问题在于：0.15、0.25、0.4kg 三档的执行接触数量分别为 1/0、0/0、1/1，而命令态均 PASS。这个结果直接证明：

**命令态几何判据对物理质量不敏感，并不意味着操作能力对物理质量具有传输性。** <Cite ref="turn207118view0"/>

另外，0.25kg 比 0.15kg 和 0.4kg 的接触结果更差，说明系统响应不是简单单调关系。它可能涉及接触模式切换、瞬态碰撞和控制路径耦合；仅凭三档扫描，不能断言系统具有“混沌”动力学。

当前最合理的做法是标记：

`mass = 0.4kg (simulation reference, not measured from source)`

并让质量扫描成为发布时的标准鲁棒性证据。

### 4. R5 与共面跨度拆分，以及 legacy/v2 并列是否成立？

**裁决：成立，并列版本化是正确选择。但有一处细节需要修正。**

你们解释的 R5 是垫中心到端面矩形的距离，而共面跨度是指尖相互之间的深度差。它们确实不是同一个指标。我撤回 v7 对这两个数存在直接数学矛盾的判断。

不过需要指出：左手 `mf=0.1190mm`，严格大于 `R5=0.116mm`，所以它不是 R5 内的合格垫。左手满足条件的是 `ff=0.0002mm` 与 `rf=0.0802mm`。右手则是 ff 和 mf。两侧仍然各有至少两垫通过，但不能写“左侧三垫均通过 R5”。

此外还需要澄清，矩形距是包含法向距离的三维最近距离，还是仅有面内矩形投影的距离。若是后者，则还必须独立加入法向偏差条件。

**legacy 冻结 + v2 并列发布：APPROVE。**

但不要复用一个不带版本后缀的 `gate1_pass`，否则未来仍会产生口径污染。

### 5. gate5/wrist 改为“判据未适配”，是否藏红项？

**裁决：认可判据不适配的技术诊断，不允许把红项变成绿项或凭空消失。**

UR5e 不具有浮动手模型的相同位姿链。用常数偏置去比较 UR5e 输出与浮代 MANO 参考，确实不能天然成为有效的机器人能力评价。你们在 v8 中对这个映射问题的归因比 v7 更严谨。<Cite ref="turn164143view0"/>

正式状态应当是：

| 门 | v8 裁决 |
|---|---|
| gate3 | FAIL — 有效，接近段支撑碰撞 |
| gate4 | FAIL — 有效，接近段关节越限 |
| gate5 | NOT EVALUABLE — UR5e 参考映射未定义 |
| wrist | NOT EVALUABLE — UR5e 参考映射未定义 |

`NOT EVALUABLE` 不是 PASS。它意味着这两个能力维度目前不能评分。

这项澄清不应该直接加到物理成功率上，但可以增加证据质量评分。

## 二、下一轮唯一任务：Approach Retarget

我建议 v9 的任务名称就定为：

**Side-Mount Approach Retarget — Collision-Free Contact Establishment**

不是继续优化 gate1 命令态微米精度，也不是追求 lift height。

本轮唯一目标是：从与原片相符的侧向预抓取位置出发，在现有 UR5e 几何约束下，构造一条不碰桌、不越限、且不提前推动盒子的接近路径，最终形成可复现的端面接触。

| 传输性 | fresh process / fresh model 重放及状态摘要一致 |
| 负结果 | 不可行时给出可达性或碰撞约束证据，不以放宽判据换 PASS |
